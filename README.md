# 得到知识红包伴侣 · 网页版 0.2.4

独立的网页插件仓库，与 Android「知识红包伴侣」仓库分开维护；不引用、构建或修改 Android 源码。

在得到网页右上角增加「知识红包」入口，点击展开 380px 宽的轻量面板。直接整理已领取的课程红包（无需先学习），显示官方到期日，点击后在官方网页阅读全文。

采用得到网页的橙色主色 `#FF6B00` 与 App 的浅橙底色 `#FFF7F2`。面板不遮罩、不锁住网页；点击外部、按 Escape 或再次点击入口即可收起。

本项目由白牙独立开发，非得到官方产品，与得到无隶属或合作关系。仅整理当前账号已有权限的内容。

## 安装

这是一个标准 Manifest V3 浏览器扩展，需要浏览器支持 MAIN world 内容脚本。没有上架商店，当前通过开发者模式加载。

1. 解压发布包，找到包含 `manifest.json` 的文件夹；也可以直接选择本仓库根目录。
2. 在 Chrome 地址栏输入 `chrome://extensions/`，开启右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的目录。使用源码安装时选择本仓库根目录。macOS 目录选择器可按 `⌘⇧G` 粘贴文件夹路径。
4. 打开或刷新 `https://www.dedao.cn/`，在 Chrome 中登录你自己的得到账号。不同浏览器的登录状态和插件缓存不会自动同步。
5. 点击右上角「知识红包」，面板会先显示缓存并按需自动刷新。工具栏的扩展按钮也可以打开得到首页和面板。

已在 Ego Lite 0.5.1.13 中实际安装并验证同步、阅读全文和刷新后的持久缓存。其他浏览器尚未实际验收。

加载后请保留此目录；Chrome 直接使用目录中的文件。下载的 ZIP 需要先解压，不能直接作为插件目录选择。可在 Chrome 工具栏的扩展菜单中固定「得到知识红包伴侣」。

m.igetget.com 访问权限用于获取领取列表；若浏览器要求确认，请检查该域名。更新代码后，在扩展管理页点击「重新加载」，再刷新得到网页。卸载可在扩展管理页移除此扩展。

## 使用

- **自动刷新**：打开面板时默认检查更新；距上次成功刷新不足 5 分钟时直接使用缓存。失败或停止后的同一页面自动重试至少间隔 1 分钟。
- **逐步加载**：先按官方权益字段显示已领取列表，再最多并行补全 4 篇文章的网页编号、到期日和学习状态；有缓存时先展示缓存。
- **学习状态**：可选择全部、未学完（隐藏已学完）或已学完，筛选设置按账号保存。使用官方完成标记、进度及音频完成状态，不会把仅打开文章视为学完。
- **刷新红包**：可随时手动刷新，不受上述 5 分钟间隔限制。读取最多 5 页、100 条领取记录，按官方 `red_packet_rights` 显示有效或失效；只为有效红包补全网页详情，已失效的条目不再重复请求正文接口。
- **继续查找**：接着读取更早的 5 页领取记录。可重复点击，直至官方接口返回没有更多记录。分页位置保存在账号缓存中；手动刷新会从最新记录开始。
- **搜索与筛选**：直接搜索文章/课程；课程、学习状态、红包状态与排序常驻两列布局，搜索框独占一行；刷新位于标题栏。
- **阅读**：再次核验权限后打开官方 PC 阅读页。正文和播放仍由得到处理。
- **停止**：停止后续同步请求，保留已读取的权益状态和已完成的文章详情。
- **清除本账号缓存**：先显示确认说明，确认后仅清除扩展的本地列表，不会删除得到账号里的文章、红包或学习记录。

搜索无结果时可点击「重置筛选」恢复；24 小时内到期的红包会突出提示。

缓存不等于实时权限；面板标注上次核验时间，实际阅读前会重新检查。切换账号后重新打开面板或刷新网页，不同账号使用各自的缓存。

## 当前范围

数据源为官方「已领取红包」列表，与 App 使用的列表对应。只领取、未学习的课程红包也会被发现。每批最多读取 100 条，历史记录多时点击「加载更早领取的红包」继续；界面不会将首批结果称为全部历史。

官方列表返回数字文章编号，插件通过官方搜索取得网页编号，再用文章接口严格核对数字编号。网页编号匹配或详情请求失败时，保留已领取接口确认的权益状态，并单独提示详情未更新；不会仅凭同名文章放行阅读。

当前仅收录课程文章（资源类型 65），不支持听书或电子书红包。不提供音频下载、离线正文、自动领取、购买或连续播放。

官方接口可能调整。权益以官方明确的布尔字段为准，网络错误不会被当作权益失效；文章接口明确返回无红包权限时更新为失效。不伪造到期日或放行失效权益。数据量上限为每个账号 5000 条本地记录。

## 权限与数据

- 声明 `storage` 与 `https://m.igetget.com/*` 的主机访问权限，后者只用于请求固定的官方已领取红包接口。内容脚本只运行在 `https://www.dedao.cn/*`。
- 不申请 Cookie、浏览历史、下载或全站访问权限。
- 从当前得到网页会话取得本账号标识；后台只向官方移动域请求本账号的领取列表，不传登录 Cookie。文章搜索和权益核验使用当前 PC 登录会话，CSRF 参数只留在页面请求中。
- 本地仅存账号分组标识、文章标识、标题、课程、官方到期文案、截止时间、核验状态和时间，学习状态和筛选偏好。
- 不保存或传送登录凭据、正文、音频地址；没有自建服务器或统计服务。

## 开发与验证

没有 npm 依赖。修改 `core.js` 或 `bridge.js` 后，先生成主世界脚本，再重新加载扩展和得到页面。仓库与安装包已包含生成文件，可直接加载。

```sh
python3 scripts/build-web-extension.py
node --test tests/web-extension/*.test.cjs
python3 scripts/package-web-extension.py
```

测试需要从仓库根目录执行。刷新按钮采用得到网页一致的橙底白字。

代码分层：`core.js` 处理字段、筛选和分页；`bridge.js` 在页面主世界调用官方接口，只返回白名单元数据；`content.js` 在隔离世界绘制面板和管理缓存；`background.js` 请求固定的官方红包列表接口，并处理扩展按钮。

`bridge-main.js` 由 `core.js` 和 `bridge.js` 生成，避免相同脚本路径跨执行世界加载时出现初始化缺失。打包命令会自动重新生成。

验证范围见 [验证说明](docs/VALIDATION.md)，数据处理方式见 [隐私政策](PRIVACY.md)。
